# homebrew-core revision used by macos.sh --sim-tools to install protobuf.
#
# The osrf/simulation gz-harmonic bottles macos.sh pours (pinned to
# gz-tap-pin.txt) ship pre-generated protobuf C++ gencode. Protobuf's runtime
# refuses gencode built against an incompatible version (the "Protobuf C++
# gencode is built with an incompatible version" poison-pill #error), so the
# installed protobuf has to be the same version those bottles were built
# against, not whatever homebrew-core currently ships.
#
# homebrew-core advances protobuf faster than OSRF rebuilds the gz bottles
# against it, so an unpinned protobuf breaks the pinned gz bottles for days at
# a time. Pinning protobuf here decouples the two: install the exact
# homebrew-core protobuf the gz pin was built for. Move this together with
# gz-tap-pin.txt whenever OSRF rebuilds the Harmonic stack against a newer
# protobuf. The bottle tags in the pinned formula must cover every macOS in
# compile_macos.yml's matrix so both legs pour instead of building from source.
#
# protobuf 36.0 (compatibility_version 5). The pinned osrf/simulation tap
# (gz-tap-pin.txt 43aee9cc) ships gz-msgs10 10.4.0_2, rebuilt on 2026-08-23
# ("gz-harmonic: rebuild dependencies", osrf/homebrew-simulation f1bf9f4f) when
# homebrew-core protobuf was 36.0, so its gencode is compatibility_version 5.
# The next osrf commit (c6c3580, "Remove bottles broken by protobuf 36.1")
# revision-bumped the bottle away, confirming 36.0 is the last protobuf these
# bottles accept: 36.1 (compatibility_version 6) and 35.1_2 (4) both trip the
# "Protobuf C++ gencode is built with an incompatible version" poison-pill.
# This formula's bottle block covers arm64_tahoe (macos-latest) and
# arm64_sequoia (macos-15), so both compile_macos.yml legs pour.
